# 项目更新监控

[技能入口](../../skills/engineering/project-monitor/SKILL.md)

## 做什么

对指定项目回答两个问题：

1. 项目用到的软件有什么变化：开源依赖、fork 或移植过来的源码、vendored 的技能、容器镜像和全局安装的工具、CI 里钉住的版本，有没有新版本或安全公告，跟项目锁定的版本有什么关系。
2. 同类产品的用户现在能做什么新事：从官方发布日志、博客或仓库里找到带日期的公告，对照本项目里相应的使用流程。

可以只要其中一个。手动跑一次会立刻出摘要，安静的一天也给结果；也可以设成每天定时检查。

## 什么时候使用

- 想知道「今天项目用到的东西有什么更新」。
- 想看同类产品最近上线了什么功能。
- 想把上面的检查设成每天自动跑。
- 想列出这个项目到底在盯哪些上游和同类产品。

调用示例：

> 跑一次这个项目今天的更新。

> 每天早上 9 点检查这个仓库的上游和同类产品更新。

Claude Code 里输入 `/xiaodd2ai-skills:project-monitor`，或直接描述需求；Codex 里写 `$project-monitor`。

## 它怎么工作

- **先建清单**：读项目说明，弄清用户和他们的常用流程；读所有模块的 manifest 和 lockfile，记下包名、锁定版本、用途和证据路径。再看 package 之外的来源：fork remote 和同步标记、vendored 许可证、源码里注明的移植、Dockerfile 的构建阶段、部署配置、插件和远程服务适配器。示例配置只说明「支持」，生产在用要另有证据。
- **按仓库归并**：同一个 monorepo 只发一次请求，但保留每个包名，别的包的发版不会混进来。
- **固定时间窗口**：「今天」从本地时区零点算起；第一次定时运行默认回看 72 小时；之后每个来源从上次成功的截止时间接着读，留一点重叠。
- **报告**：先写重要的变化。依赖给出锁定版本、新版本、受影响的本地功能和一个具体的兼容性检查方法；同类产品写清用户现在能做什么。每条附官方链接。例行补丁和预发布版本归到一起。
- **记进度**：每个来源的截止时间、失败的来源、清单版本和已报告的事件，按「仓库 + 服务路径」存在仓库外的用户本地目录，不写进被监控的仓库。同一事件不重复报告。

## 常见问题

**会改动我的仓库吗？**

不会。它在指定的版本上读取文件，不切换你当前的检出；检查进度写在仓库外。

**同类产品是怎么选的？**

优先用你点名的产品。没点名时选少数几个面向同一类用户、解决同一类工作的产品，并写下入选理由和官方信息来源。

**内部仓库的信息会被拿去外部搜索吗？**

不会。内部仓库地址、路径、manifest 内容和凭据不出现在外部搜索词里。

**某个来源访问失败怎么办？**

换一个核实过的替代来源，原来源标为待补，下次接着查。只有完整读完一个来源的时间窗口并保存结果，才推进它的截止时间。

**在 Claude Code 里设的定时能一直跑吗？**

不能。Claude Code 的定时任务（`CronCreate`，2.1.332 上验证）只存在于当前会话：关掉会话就没了，只在会话空闲时触发，循环任务 30 天后自动过期。要长期每天跑，需要另配本机定时（例如 launchd 或 cron 调用 `claude -p`）。没有持久定时能力时，技能会给出手动运行的方法，并说明还差哪一步。

**和 Dependabot、Renovate 有什么区别？**

它们负责给依赖开升级 PR。这个技能不改代码，只出摘要；范围也更宽，包括 fork 和移植的上游、镜像和工具，以及同类产品的新功能。

## 完成标准

- 报告写明检查的时间窗口和覆盖了哪些来源，失败的来源单独列出。
- 每条重要变化都有官方链接；依赖类给出锁定版本、新版本和具体的兼容性检查方法。
- 预览版、草稿和撤回的版本标注准确，草稿不计入发版数。
- 检查进度和已报告事件已保存在仓库外，下次不会重复报告。
- 设了定时的，确认返回的日程和启用状态；做不到持久定时时，已经说明手动运行方法和还差的步骤。
